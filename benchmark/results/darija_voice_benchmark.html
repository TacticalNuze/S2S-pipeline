Benchmark report · 21 October 2026

Darija voice assistant on one 16 GB GPU

Three local language models tested as the “brain” of a Moroccan Darija speech-to-speech assistant, running entirely on a consumer NVIDIA RTX 5060 Ti. We measured how fast each starts answering, whether it fits in video memory beside the speech models, and how natural its Darija sounds.

Video memory

Does the full voice stack fit on the GPU?

The speech recognition and synthesis models need about 4.5–5 GiB on top of the language model and the 1 GiB Windows keeps for the display. The card has 15.9 GiB.

Qwen3.8 27B was measured alone (13.3 GiB including Windows). Its full-stack bar adds the ASR + TTS share measured with Atlas-Chat, so it is a projection: we did not load all three, because it would exceed the card.

Tuning

Multi-token prediction on Qwen3.8 27B

The Qwen models carry a built-in draft layer that guesses upcoming tokens, which the main model then checks in one pass. We tested how far ahead it should guess, on a 600-token English answer.

Decode speed by draft depth

Tokens per second on a 600-token answer. The share of drafted tokens accepted is shown under each column.

What we kept

  • Drafting 2 tokens ahead is fastest: 46.9 tok/s, 1.7× the speed without it, for 0.8 GiB more memory.
  • Going further ahead wastes work: at 3 tokens only half the drafts are accepted, and speed drops to 43.3 tok/s.
  • On short Darija replies fewer drafts are accepted (about 15–60%), so the gain there is smaller, about 1.3×.
  • Thinking mode is switched off for every model. With it on, the user would wait through hidden reasoning before hearing anything.

Method

  • Six Darija prompts (greeting, sightseeing, recipe, travel time, reassurance, a joke) sent through the OpenAI-compatible streaming API.
  • The assistant’s real system prompt: reply in Darija, Arabic script, one or two short sentences.
  • One warm-up request, then one run per prompt. Temperature 0.7, max 200 tokens.
  • First token: first reply text received. First sentence: first . ! ? ؟ or line break.
  • Speed from llama.cpp’s own timings. Memory from nvidia-smi during one real ASR → LLM → TTS pass.

Server settings

Common to all three: every layer on the GPU, flash attention, 8-bit KV cache, one conversation at a time.

llama-server -m <model.gguf> --n-gpu-layers all --flash-attn on -ctk q8_0 -ctv q8_0 --parallel 1 --jinja

# Qwen3.8 27B and Qwen3.5 9B
-c 16384 (27B) / 8192 (9B)  --spec-type draft-mtp --spec-draft-n-max 2 --gpu-layers-draft all
--reasoning off  --temp 0.7 --top-p 0.8 --top-k 20 --min-p 0 --presence-penalty 1.5

# Atlas-Chat 9B (Gemma 2 based: no thinking mode, no MTP layer)
-c 8192  --temp 0.7 --top-p 0.9 --min-p 0.05 --repeat-penalty 1.1
Limits

What this benchmark does not show yet

  • End-to-end voice latency. We timed each stage separately. The full time from the user stopping to the first audible reply in the live assistant has not been measured yet.
  • Cloud comparison. The same prompts have not yet been run against a cloud model.
  • Variance. One run per prompt at temperature 0.7; repeat runs could move individual timings by roughly ±10%.
  • Quality. Six prompts and one informal reviewer. A proper evaluation needs more prompts and native-speaker ratings.
  • Other hardware. All figures are for this one machine. Cards with more memory could run the 27B beside the speech models.
